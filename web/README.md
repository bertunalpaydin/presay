# Presay website

Check a script before you say it. Paste an interview answer or a talk and Presay
marks the words a listener is most likely to mishear, explains why, suggests
easier words, and lets you practise out loud with a speech model that runs in
your browser. Nothing is uploaded.

Live at https://presay.app. This folder is the website; the first version of the
project, a desktop app, is in [`../desktop`](../desktop).

No script yet? Practice has 48 short texts from everyday situations (job
interviews, presentations, meetings, calls, travel and more) to read aloud, each
with its hard words marked, and endless rounds of ten single words that are
hard for your first language. A script with only a few marked words gets its
round filled up with these.

Marks and tips depend on your first language: Arabic, Chinese (Mandarin),
French, German, Hindi, Japanese, Portuguese (Brazil), Russian, Spanish or
Turkish. The site guesses it from the browser's languages (Turkish if none of
them is on the list) and you can change it at any time. Explanations of why a
word is hard and how to say it can be shown in English or in that language;
the rest of the site stays in English.

## What is in this folder

```
site/                 the website: deploy this folder as it is
  index.html
  assets/             styles and fonts
  js/                 the app (plain JavaScript modules, no build step)
    languages.js      the first-language profiles: weights, slips, tips
    native/           the same explanations in each first language
    practice-texts.js the texts to read aloud on the Practice page
    risk-rules.js     sound features, slips and the scoring shared with the build
  data/               word data (generated by scripts/build-data.mjs)
  vendor/             versions.js: pinned versions of the files loaded from the CDN
  favicon.svg         the logo; scripts/make-images.mjs draws the other icons from it
  og.png, favicon.ico, apple-touch-icon.png   share preview and icons
  robots.txt, sitemap.xml
  _headers            security headers for Cloudflare Pages
  licenses.txt        licences of everything the site serves
scripts/
  build-data.mjs      rebuilds site/data from the CMU dictionary, WordNet and SCOWL
  blocklist.mjs       words that are never suggested or printed
  vendor.mjs          copies fonts and licence texts into site/ and pins versions
  make-images.mjs     draws the share preview and icons with the site's fonts
  serve.mjs           local web server with the same headers as Cloudflare
tests/                unit tests and browser tests
docs/ARCHITECTURE.md  how it works and why it is built this way
```

## Run it on your computer

You need Node.js 20 or newer. Running the site needs no `npm install`.

```bash
cd web
npm run dev
```

Open http://localhost:5173. The microphone works on `localhost` without HTTPS.

## Tests

```bash
npm install            # only for tests and for rebuilding data
npm test               # unit tests (text, alignment, profile, word data, languages, audio)
npm run test:browser   # end-to-end test in headless Chrome
```

On a Mac, point the browser test at Chrome:

```bash
CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" npm run test:browser
```

`tests/real-asr.mjs` runs a real Whisper model with every file served locally. It
is skipped unless `MODELS_DIR` and `SAMPLE` are set (see the comment at the top of
the file).

GitHub Actions runs `npm test` on every push (`.github/workflows/tests.yml` at
the top of the repository).

## Put it online for free (Cloudflare Pages)

1. Create a free Cloudflare account at https://dash.cloudflare.com/sign-up.
2. Go to **Workers & Pages**, choose **Create**, then the **Pages** tab, then
   **Connect to Git**, and pick the repository.
3. Use these build settings:
   - Framework preset: **None**
   - Build command: leave it empty
   - Build output directory: `site`
   - Root directory (under **Advanced**): `web`
   - Environment variable: `SKIP_DEPENDENCY_INSTALL` with the value `1`
4. Save and deploy. The site appears at `https://<project-name>.pages.dev`.
   Every push to `main` deploys again automatically.

The site has no build step. The root directory keeps Cloudflare away from the
desktop app's Python files, and the variable stops it installing the packages in
`package.json`, which only the scripts and tests use.

Without Git: on the same Pages screen choose **Upload assets** and drag the
`web/site` folder in.

## Add your own domain (the only cost)

1. In the Cloudflare dashboard open **Domain Registration > Register Domains**,
   search for the name and buy it. Cloudflare sells domains at cost.
2. Open the Pages project, go to **Custom domains**, choose **Set up a custom
   domain** and enter the domain. Add it here rather than creating a DNS record
   by hand: Cloudflare then creates the record and the HTTPS certificate.

A `.app` domain only works over HTTPS, so the address starts working once the
certificate is ready, which can take a few minutes.

`site/index.html`, `site/robots.txt` and `site/sitemap.xml` give
https://presay.app as the site's address. Change them if you deploy it
somewhere else.

## What it costs to run

| Part | Where it runs | Cost |
| --- | --- | --- |
| Website files | Cloudflare Pages, free plan | free |
| Speech recognition | on each visitor's device (Whisper in the browser) | free |
| Model files | downloaded once per visitor from Hugging Face | free |
| Speech library and runtime (Transformers.js, WebAssembly) | jsDelivr CDN, with unpkg as a fallback | free |
| Word list and settings | the visitor's browser (localStorage) | free |
| Domain | Cloudflare Registrar | about $14 a year for a .app |

There are no API keys, no database and no server. Nothing here sends a bill.
Adding a paid API or server-side transcription later would change that;
neither is used now.

## Rebuild the data or update Transformers.js

```bash
npm install
npm run build:data     # regenerate site/data/*.json and site/js/data-version.js
npm run vendor         # pin new versions, copy fonts and licences into site/
npm run images         # redraw og.png and the icons (after changing name, colours or fonts)
```

Commit the changed files in `site/` afterwards; the site itself has no build step.

## Add or tune a first language

Each language is one entry in `site/js/languages.js`: how many points each sound
feature is worth, which slips are typical (for example `W_V`, "west" heard as
"vest") and a few tips. Its
explanations in its own language live in `site/js/native/<code>.js`.

After changing weights or slips, run `npm run build:data` (the suggested
synonyms depend on the scores) and `npm test`. The tests check that every
example in the tips really appears in the data, that every suggestion is easier
for every language, and that every sound a language counts has an explanation
in that language which keeps the same English example words.

## Self-host the model files (optional)

If Hugging Face or the CDNs are blocked somewhere, host the files yourself and
add this before the `js/app.js` script tag in `site/index.html`:

```html
<script>
  window.PRESAY_CONFIG = {
    modelHost: 'https://files.example.com/models/', // instead of https://huggingface.co/
    wasmBase: 'https://files.example.com/ort/',     // folder with ort-wasm-simd-threaded.jsep.mjs and .wasm
    libraryUrl: 'https://files.example.com/transformers.min.js', // instead of the CDN copy of Transformers.js
    models: { small: 'onnx-community/whisper-small.en', base: 'onnx-community/whisper-base.en', tiny: 'onnx-community/whisper-tiny.en' },
  };
</script>
```

## Privacy

Scripts and recordings stay on the device. The word list and settings are saved
in the browser's local storage, and "Export my words" makes a backup file. There
are no accounts, no analytics and no cookies.
